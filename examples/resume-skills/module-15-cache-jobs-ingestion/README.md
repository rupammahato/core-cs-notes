# M15: Caching, Background Jobs and Data Ingestion

Examples accompanying Part 17: local cache algorithms, a file-backed SQLite job protocol, real CSV/XLSX/XML/PDF parsers and restartable CSV imports.

## Run

From the repository root, with the prepared environment:

```powershell
./examples/resume-skills/module-15-cache-jobs-ingestion/.venv/Scripts/python.exe -X utf8 examples/resume-skills/module-15-cache-jobs-ingestion/verify.py
```

To recreate it, select Python 3.12, create .venv here, install requirements.lock.txt and run pip check. The recorded installation used cached wheels with --no-index. The lock pins versions without hashes; environments/wheelhouses are ignored. Global packages are unchanged.

Recorded: CPython 3.12.10, SQLite 3.49.1, openpyxl 3.1.5, et-xmlfile 2.0.0, defusedxml 0.7.1, pypdf 6.19.0. The runner creates a verified-owned temporary directory, fresh databases and child processes with deadlines. Connections close before cleanup. It starts no persistent listener and does not use port 3000 or existing services. Generated source files are in-memory bytes; user PDFs are untouched.

Cache checks use actual threads and a controlled monotonic clock: eight callers, one loader and seven observed waiting followers; invalidation prevents an old fill repopulating the cache. The local epoch does not cancel old responses or coordinate other processes.

Job checks use real separate SQLite connections. Claims serialize, lease tokens rotate, stale completion/failure is rejected, and local effect/completion commit together. Manual lease time and injected application interruptions are not machine-crash/failover tests. The deterministic retry helper omits jitter and is not a Cloud Tasks emulator.

Parser checks run actual libraries on generated bytes, including formula/entity/archive-budget rejection and PDF text/empty/encrypted/page policies. They are bounded teaching adapters, not a hostile-input resource sandbox or an OCR engine.

Imports validate bounded CSV input, bind an import key to immutable bytes, conditionally upsert tenant/source identities and commit each batch's checkpoint with its data. Interrupted and concurrent restarts preserve records and source-version rules. XML/XLSX normalize into the same model; PDF returns reviewable evidence text. Only CSV is wired to the durable importer.

## Files

- cache.py: process-local TTL/LRU, negative caching, copies, single-flight and late-fill epoch guard.
- store.py / jobs.py: local schema, explicit connection/transaction lifecycle, durable operation identity, leases/tokens and terminal state.
- ingestion.py: parser budgets, normalization, conditional upserts and atomic progress.
- checks.py / fixtures.py / verify_*.py / verify.py: assertions, generated inputs and isolated verification.
- *-results.json / verification-output.txt: recorded behavior and runtime.
- content-validation.json / site-validation.json / validation-summary.json: chapter fidelity and website evidence.
- site-smoke.mjs: temporary loopback website checks, then closes its owned server.

The chapter embeds cache.py, store.py, jobs.py and ingestion.py exactly.

## Scope

Redis and Cloud Tasks are researched documentation bridges, not executed services. No managed queue, cloud credentials, HTTP/OIDC delivery, provider side effect, cross-process cache invalidation, object storage, OCR, crash/power-loss recovery or production load benchmark is exercised. External effects need their own idempotency/reconciliation protocol. The proposed import-service architecture labels its additional integrations explicitly.
